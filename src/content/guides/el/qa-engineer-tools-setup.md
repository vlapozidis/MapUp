🧰 Δεν χρειάζεται να είσαι προγραμματιστής για να είσαι πολύ καλός QA engineer — αλλά μερικά εργαλεία κάνουν τη δουλειά πολύ πιο εύκολη από την πρώτη μέρα.

## Γιατί έρχεται πρώτο αυτό

Ένα bug report είναι πιο πειστικό όταν έχεις κολλήσει μέσα ένα request και ένα response, και το «έχεις ελέγξει το console;» σταματά να είναι τρομακτική ερώτηση μόλις ξέρεις πού είναι το console. Τίποτα από αυτά δεν είναι περίπλοκο — απλά πρέπει να είναι εγκατεστημένα πριν βρεθείς στη μέση ενός ticket να ψάχνεις.

## 🧰 Εργαλεία για ρύθμιση

- **Ένας code editor** — το [VS Code](https://code.visualstudio.com/) είναι η ασφαλής επιλογή. Δεν χρειάζεται να γράφεις κώδικα για να έχεις όφελος από αυτό: μόνο το find-in-file σε όλο το project και ένα ενσωματωμένο terminal panel αξίζουν την εγκατάσταση.
- **Postman** — [postman.com/downloads](https://www.postman.com/downloads/). Για να στέλνεις χειροκίνητα API requests και να βλέπεις τι επιστρέφει — status codes, headers, response bodies — χωρίς να χρειάζεται να το κάνει ένας developer για σένα.
- **Browser DevTools** — είναι ήδη ενσωματωμένα στο Chrome, στο Edge και στο Firefox, οπότε δεν χρειάζεται εγκατάσταση. Απλά φρόντισε να ξέρεις πώς τα ανοίγεις: **F12**, ή δεξί κλικ οπουδήποτε στη σελίδα → **Inspect**. Τα tabs **Console** και **Network** είναι τα δύο που θα ζεις μέσα τους.

## 🏷️ Δεξιότητες που θα αποκτήσεις

`IDE Setup` `Postman` `Browser DevTools`

## 💡 Συμβουλές

- Μην αγχώνεσαι ακόμα για το Selenium ή για τη ρύθμιση browser driver — αυτό καλύπτεται μόλις φτάσεις στο θέμα automation-fundamentals. Δεν χρειάζεται να εγκαταστήσεις τίποτα τώρα.
- Στα DevTools, το tab Network καταγράφει requests μόνο *όσο είναι ανοιχτό* — άνοιξέ το πριν αναπαράγεις το πρόβλημα, όχι μετά.
- Αποθήκευε μερικά πραγματικά API requests στο Postman καθώς προχωράς· ένα έτοιμο παράδειγμα είναι καλύτερο από το να το ξαναγράφεις από μνήμη κάθε φορά.
